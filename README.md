# CTest

A simple full-stack notes application built with Django REST Framework, PostgreSQL, and Flutter.

## Project Overview

This project is a learning-oriented full-stack application with:

- Django backend
- Django REST Framework API
- PostgreSQL database
- Flutter frontend
- Notes and Categories
- Note-to-Category relationship using ForeignKey
- API validation
- Flutter ↔ Django integration

The current version supports reading and creating notes. Notes can optionally belong to a category.

## Backend

The backend is built with Django and Django REST Framework.

### Python Environment

Create and activate a virtual environment:

```powershell
python -m venv .venv
```

Activate it on Windows:

```powershell
.\.venv\Scripts\Activate.ps1
```

Install Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

### Environment Variables

Create a `.env` file in the project root.

Use `.env.example` as a template.

The backend uses environment variables for database configuration and the Django secret key.

### Database

The project uses PostgreSQL.

Configure the following variables in `.env`:

```env
DB_NAME=
DB_USER=
DB_PASSWORD=
DB_HOST=
DB_PORT=

DJANGO_SECRET_KEY=
```

Run migrations:

```powershell
python manage.py migrate
```

Create an admin user when needed:

```powershell
python manage.py createsuperuser
```

Run the Django development server:

```powershell
python manage.py runserver
```

The backend API will then be available at:

```text
http://127.0.0.1:8000/
```

## API Endpoints

### Notes

Get all notes:

```http
GET /api/notes/
```

Get one note:

```http
GET /api/notes/<id>/
```

Create a note:

```http
POST /api/notes/
```

Example request:

```json
{
  "title": "My note",
  "content": "Hello from the API",
  "category": 2
}
```

The `id` and `created_at` fields are generated by the backend and are not supplied by the client.

### Categories

Get all categories:

```http
GET /api/categories/
```

Get one category:

```http
GET /api/categories/<id>/
```

Categories are currently read-only through the API.

## Validation

The backend validates incoming data through Django REST Framework serializers.

For example, note titles must contain at least three non-whitespace characters.

An invalid category ID is also rejected by the API.

Example validation response:

```json
{
  "title": [
    "Title must be at least 3 characters long."
  ]
}
```

## Flutter Frontend

The frontend is located in:

```text
frontend/
```

Install Flutter dependencies:

```powershell
cd frontend
flutter pub get
```

Run the web application:

```powershell
flutter run -d chrome
```

The Flutter application currently:

- Retrieves notes from the Django API
- Retrieves categories from the Django API
- Displays notes and their categories
- Provides a form for creating notes
- Sends new notes to the Django API
- Displays backend validation errors

## Current Scope

This is currently a small learning project.

The implemented functionality includes:

- Note CRUD API on the backend
- Category model
- ForeignKey relationship between Note and Category
- Nested category representation when reading notes
- Separate read/write serializers
- Serializer validation
- Flutter web integration
- Creating notes from Flutter

Editing and deleting notes from the Flutter UI are not implemented yet.

## Security Notes

Sensitive values such as the Django `SECRET_KEY` and database password are stored in `.env` and should not be committed to Git.

For production deployments, development-only settings such as permissive CORS configuration must be replaced with restricted production settings.
